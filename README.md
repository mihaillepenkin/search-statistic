```bash
docker-compose up --build
```

### Примеры запросов

# Healthcheck
```bash
curl http://localhost:8080/health
```
# → {"status":"ok"}

# Топ-10 популярных запросов
```bash
curl http://localhost:8080/top/10
```

# Добавить слово в стоп-лист
```bash
curl -X POST http://localhost:8080/stoplist \
  -H "Content-Type: application/json" \
  -d '{"word":"spam"}'
```

# Удалить слово из стоп-листа
```bash
curl -X DELETE http://localhost:8080/stoplist \
  -H "Content-Type: application/json" \
  -d '{"word":"spam"}'
```

### Контракт данных

{
  "query": "iphone 15 pro max",
  "timestamp_sec": 1718000000,
}

Поле query содержит в себе запрос
Поле timestamp_sec пока не используется, в текущей реализации сервис считает, что запрос был сделан в момент, когда сервис получил сообщение от брокера
Но в будущем понадобится, чтобы получать статистику с точным моментом получения запроса

### Обоснование архитектуры: выбор структур данных


### Скользящее окно: `chan map[string]int` (ёмкость = 300. 1 объект - 1 секунда)
используется для хранения бакетов(мап), содержащих инфу о всех запросах за соотвествующую секнду
| Критерий | Решение |
|----------|---------|
| **Зачем нужна`** | необходимо, чтобы была возможность каждую секунду быстро удалять старые запросы(старее, чем 5 минут) и добавлять новые, тем самым легко контролировать жизненный срок запроса|
| **Почему канал** | Встроенная FIFO-гарантия. Сдвиг окна = `<-ch` (вычесть старое) + `ch <- new` (добавить новое). |

### 🔹 Глобальный агрегатор: `map[string]int`
используется для хранения глобальной информации о суммарном количестве запросов
| Критерий | Решение |
|----------|---------|
| **Зачем нужна`** | Для ответа на запрос не нужно будет конконтенировать все мапы из очереди, необходимо просто взять N максимальных значений, что намного быстрее|
| **Почему не БД** | Сетевая латентность займет много времени. In-memory доступ — ~10 нс. Сложная работа с очисткой данных. |

### 🔹 Кэш топа: `atomic.Pointer` + TTL 500 мс
| Критерий | Решение |
|----------|---------|
| **Зачем кэш** | Сортировка 150k элементов занимает ~5 мс. При 10 000 RPS без кэша — 50 секунд CPU в секунду → сервис упадёт. |
| **Почему `atomic.Pointer`** | Чтение указателя — атомарная операция, **0 мьютексов**, 0 блокировок. 99% запросов отдают кэш за `<0.05 мс`. |
| **Почему TTL** | Read/write ratio 10–50:1. Пересчёт раз в 500 мс снижает нагрузку на сортировку в 50×. Eventual consistency <0.5 сек незаметна для пользователя. |

### 🔹 Стоп-лист: `atomic.Pointer[map]` (Copy-on-Write)
| Критерий | Решение |
|----------|---------|
| **Почему CoW** | Обновления стоп-листа — раз в дни. Чтение — на каждый запрос. Копирование мапы (1000 слов) занимает ~10 мкс и не блокирует читателей. |
| **Почему не `RWMutex`** | Даже `RLock` при 10 000 RPS создаёт contention. `atomic.Pointer` — одно атомарное чтение, без мьютексов. |
| **Почему не Bloom/Trie** | Точное совпадение слов достаточно для задачи. Bloom даёт ложные срабатывания (нельзя скрывать легитимные тренды), Trie — оверхед для 1000 слов. |
| **Почему map** | Позволяет за O(1) проверять наличие слова в стоп листе, что необходимо для фильтрации, которая происходит при ответе на запрос top|


### 💡 Ключевые принципы
1. **Read-heavy оптимизация**: все тяжёлые операции вынесены в фон и кэшируются.
2. **Lock-free чтение**: `atomic.Pointer` позволяет читать кэш и стоп-лист без мьютексов.
3. **Предсказуемая память**: фиксированный буфер, очистка нулевых счётчиков → стабильный RSS.
4. **Честные компромиссы**: in-memory → потеря данных при рестарте; TTL-кэш → eventual consistency <0.5 сек. Эти ограничения документированы и приемлемы для задачи.

### Производительность и нагрузочное тестирование

Тестирование проведено утилитой [`vegeta`](https://github.com/tsenart/vegeta) на локальной машине. Сервис предварительно загружен 15 000 поисковых событий из брокера.

#### Сценарий: Стресс-тест (10 000 req/s)
| Метрика | Значение |
|---------|----------|
| Success | 99.97% |
| Latency p50 | 524 µs |
| Latency p95 | 897 µs |
| Latency p99 | 4.36 ms |
| Throughput | 9997 req/s |

#### Как воспроизвести
```bash
docker-compose up -d

go run producer.go

echo "GET http://localhost:8080/top/10" > targets.txt

vegeta attack -rate=10000 -duration=10s -targets=targets.txt -output=results.bin

vegeta report results.bin
```
